# Web entities: supporting slices

> Ten entities, `comment` through `workspace-settings`, plus the root admin-keys spec. Source: `apps/web/src/entities/{comment,contact-message,media,open-source,project,social-link,tag,tech-stack,user-profile,workspace-settings}`, `apps/web/src/entities/admin-query-keys.spec.tsx`.

## Layout

```text
apps/web/src/entities/
├── comment/            api/ 5 actions · model/ types · query/ factories + 4 hooks · ui/ thread
├── contact-message/    api/ send, admin list, delete · model/ types · query/ factory + hook · no ui/
├── media/              api/ upload, video, delete, list · model/ file key only
│                       query/ factories + 6 hooks · ui/ media-card
├── open-source/        api/ GitHub read · ui/ repo rows (fetch, grouping, types and ledger: `@byte-of-me/github`)
├── project/            api/ CRUD + admin/public reads + by-id · model/ types, admin include, title · query/ factories + 3 hooks · ui/
├── social-link/        api/ one public read · model/ types only
├── tag/                api/ CRUD + reads + by-id · model/ types, admin include, display name · query/ factories + 3 hooks · ui/ badge
├── tech-stack/         api/ CRUD + reads + by-id · model/ types · query/ factories + 3 hooks · ui/ 2 components
├── user-profile/       api/ save + reads · model/ types · query/ `useUserProfile` · ui/ greeting, quote
├── workspace-settings/ api/ read, patch, compression · query/ factory + 2 hooks · no model/
└── admin-query-keys.spec.tsx   root spec (see bullet below)
```

- The zod schemas, query-key factories, upload constraints and cache-tag maps of these entities are not in `model/` any more: they are `@byte-of-me/contracts/<slice>` (`packages/contracts/src/<slice>/`, see [tooling-and-small-packages.md](tooling-and-small-packages.md)). `model/` keeps what imports Prisma types (`types.ts`, the `admin-*-include.ts` files) or app code (`media-file-key.ts` needs `nanoid`, `tag-display-name.ts` and `admin-project-title.ts` read `./types`). `PublicProjectFilters` moved with `projectKeys`. `media` keeps no `model/index.ts`, so its slice barrel does not export `model`. `open-source`, `social-link` and `workspace-settings` have no slice barrel (nothing imported it): their callers import the file by path.
- No `'use server'` under `api/`: `apps/web/src/entities/media/api/upload-single-media.ts` and `apps/web/src/entities/media/api/upload-video-direct.ts` (client code), `apps/web/src/entities/workspace-settings/api/get-workspace-settings.ts` (React `cache()` helper).
- 28 spec files in the slice (re-counted with `find` after the GitHub grouping and ledger specs moved to `packages/github`). `open-source` and `social-link` have no query keys.
- No entity lacks server actions. `open-source` (one GitHub read) and `social-link` (one read) have no write action; social links are written by `apps/web/src/entities/user-profile/api/save-profile.ts`.
- `admin-query-keys.spec.tsx` asserts that `adminList()` invalidation stales every page and picker key (blog, education, company, project, tag) but no outside key, and that a server-prefetched first page hydrates with no client fetch.

Table paths are relative to `apps/web/src/entities/<entity>/` (`api/`, `model/`, `ui/`, `query/`), to `apps/web/src/` (`features/`, `widgets/`, `app/`) or, where marked contracts, to `packages/contracts/src/<entity>/`.

## Key flows

- Admin CRUD: `apps/web/src/widgets/dashboard/tag-manager/ui/tag-manager.tsx` (`useCrudManager`) → `apps/web/src/entities/tag/api/*.ts` (A → P → Prisma → R) → managers pass `keys` (`<x>Keys.all`, `<x>Keys.detail`); a save invalidates `all` and drops `detail(id)`.
- Public cached read: `apps/web/src/entities/<x>/api/get-*.ts` → `handlePublicAction` → `withPublicActionHandler` (`apps/web/src/shared/api/public-action-template.ts`) → `unstable_cache` keyed by `cacheTags`; the write action's `revalidateTag` clears it.
- Blog comments: `apps/web/src/features/public/blog-comment/ui/blog-comment-section.tsx` → `usePostComment` (`apps/web/src/entities/comment/query/use-post-comment.ts`, a `useServerMutation`) → `postComment` (requireUser, 5 per min per user, published-blog and parent checks, mail in `after()`); the thread is read by `useCommentInfiniteQuery` (`apps/web/src/entities/comment/query/use-comment-infinite-query.ts`), uncached.
- Blog interaction counts (like, clap): the count and the reader's own state are read through `useBlogInteractionState` (`apps/web/src/entities/blog/query/use-blog-interaction-state.ts`, over `blogQueries.interaction` in `blog-queries.ts`) and `apps/web/src/entities/blog/api/get-blog-interactions-for-user.ts`. The toggle is `apps/web/src/entities/blog/api/toggle-blog-interaction.ts`. Both are blog-entity actions, not feature code.
- Image upload: each form calls `useScopedImageUploader(scope)` (`apps/web/src/entities/media/query/use-image-upload.ts`; `project-form.tsx` is one caller) → `apps/web/src/entities/media/api/upload-single-media.ts` compresses in the browser (settings memo 30 s) → images: `uploadMedia` compresses again on the server (`compressImage` in `apps/web/src/entities/media/api/upload-media.ts`); video: `uploadVideoDirect` (prepare → PUT to signed URL → finalize).
- Settings: `apps/web/src/app/[locale]/(protected)/dashboard/layout.tsx` prefetches `workspaceSettingsQueries.current()` into a `HydrationBoundary`; `useWorkspaceSettings()` reads it. A write goes through `useUpdateImageCompression` → `updateWorkspaceSettings`, which merges jsonb in SQL, revalidates WORKSPACE_SETTINGS, and returns the row, which the hook puts back into the query.
- Profile: `apps/web/src/features/dashboard/update-profile/lib/use-profile-controller.tsx` (`useServerMutation`) → `saveProfile` (one `$transaction` for profile, translations, social links) → R USER and SOCIAL after commit.
- Contact form: `apps/web/src/features/public/contact-me/ui/form/contact-form.tsx` → `sendContactMessage` (3 per 10 min per IP, mail in `after()`, R CONTACT, which `apps/web/src/features/dashboard/dashboard-stats/lib/get-dashboard-stats.ts` reads).
- Open source: `getOpenSourceContributions` → GitHub GraphQL (`packages/github/src/open-source/fetch-merged-pull-requests.ts`) → `groupByRepo` → cached 3600 s under OPEN_SOURCE; no write invalidates it.

## Recipes

1. Add an admin action to a CRUD entity (example: tag)
   1. Schema: `packages/contracts/src/tag/tag-schema.ts`, exported from `@byte-of-me/contracts/tag`.
   2. Action: `apps/web/src/entities/tag/api/create-tag.ts` pattern. `'use server'`, `requireAdmin()` before `try`, `parseInput` inside `try`, Prisma, `revalidateTag(CACHE_TAGS.X, 'max')` after the write (the tag actions loop over `TAG_MUTATION_TAGS`, which also covers BLOG and PROJECT: `packages/contracts/src/tag/revalidation.ts`), `ApiResponse` with `errorMsg`.
   3. Export it from `apps/web/src/entities/tag/api/index.ts`, unless it is a picker (see gotchas).
   4. Manager: `useCrudManager` in `apps/web/src/widgets/dashboard/tag-manager/ui/tag-manager.tsx`; pass `keys: { all: tagKeys.all, detail: tagKeys.detail }` from `packages/contracts/src/tag/query-keys.ts`. A save invalidates `all` and drops the `detail(id)` record the dialog loads (`useAdminTagById`), so the pre-save record is not left cached.
2. Add a cached public read (example: projects)
   1. Params schema: `packages/contracts/src/project/public-project-schema.ts`; call `parseInput` first.
   2. Wrap with `handlePublicAction` and `withPublicActionHandler(..., { cache: true, cacheKey: [every closure arg], cacheTags: [CACHE_TAGS.X] })`. Pattern: the options object of `apps/web/src/entities/project/api/get-paginated-public-projects.ts`.
   3. Client and server prefetch call the same factory: `apps/web/src/app/[locale]/(public)/projects/page.tsx` (`projectQueries.publicList`) and `apps/web/src/entities/project/query/use-public-project-list.ts` (the client hook spreads the same options).
3. Add a workspace setting (no migration: `preferences` is `Json @default("{}")`, `model WorkspaceSettings` in `packages/db/prisma/schema.prisma`)
   1. Add the field to `workspaceSettingsSchema` and to `WORKSPACE_SETTINGS_DEFAULTS` in `packages/contracts/src/workspace-settings/settings-schema.ts` (`workspaceSettingsSchema` is file-private; the package exports its `z.infer` as `WorkspaceSettings`). `workspaceSettingsPatchSchema` is its `.partial()`, so the action needs no change.
   2. Prefetch `workspaceSettingsQueries.current()` in the dashboard layout; read it on the client with `useWorkspaceSettings()` (`apps/web/src/entities/workspace-settings/query/use-workspace-settings.ts`).
   3. Write with `updateWorkspaceSettings({ field: value })` (`apps/web/src/entities/workspace-settings/api/update-workspace-settings.ts`).

## Gotchas

- `withPublicActionHandler` appends the locale to `cacheKey` and nothing else; page, ids and filters must be in the key yourself (`withPublicActionHandler` in `apps/web/src/shared/api/public-action-template.ts`).
- No `CACHE_TAGS.COMMENT` or `CACHE_TAGS.MEDIA` read exists in `apps/web/src`, so their `revalidateTag` calls invalidate nothing today.
- Every `revalidateTag` call in `apps/web/src` passes `'max'`; none passes `'default'`.
- `hideComment` lets the author hide their own comment and the site owner hide any (`apps/web/src/entities/comment/api/hide-comment.ts`). The admin test is `getAuthenticatedAdmin()`, which checks role and owner identity, not `user.role` alone. An anonymous caller rejects at `requireUser()` (outside the `try`). A signed-in user who is neither gets `errorCode: 'forbidden'` on someone else's comment and `not-found` on a missing one, with no write. `apps/web/src/entities/comment/api/hide-comment.spec.ts` pins the cases. Only the admin `setCommentVisibility` can unhide.
- `apps/web/src/entities/project/api/index.ts` and `apps/web/src/entities/tag/api/index.ts` omit the picker actions, so the query factories import them by path (`apps/web/src/entities/project/query/project-queries.ts`, `apps/web/src/entities/tag/query/tag-queries.ts`). `apps/web/src/entities/user-profile/api/index.ts` omits its helpers on purpose (its header comment says why).
- `getWorkspaceSettings` fails closed: a signed-out caller gets the `requireAdmin()` refusal, not defaults (`getWorkspaceSettings` in `apps/web/src/entities/workspace-settings/api/get-workspace-settings.ts`). A failed read in `useWorkspaceSettings()` throws to the error boundary; it never renders defaults.
- `deleteMedia` deletes the row first (`apps/web/src/entities/media/api/delete-media.ts`). The storage object follows, best effort; a failed storage delete is logged and leaves an orphan object. A failed row delete keeps the file.
- `projectKeys.publicList` and `tagKeys.infinite` have no locale segment, but their actions resolve titles by locale (`apps/web/src/entities/project/api/get-paginated-public-projects.ts`, `apps/web/src/entities/tag/api/get-paginated-public-tags.ts`). `tagKeys.options` includes one for this reason.
- The three picker hooks name their retry differently: `useTagOptions` and `useProjectReferenceOptions` return `retry`; `useTechStackOptions` returns `refetch`, which `apps/web/src/widgets/dashboard/company-manager/ui/company-form.tsx` reads. Rename the hook and its reader together.
- `getAllAdminTechStack` is capped at `ADMIN_OPTIONS_LIMIT` (500) for the picker and the manager alike; rows past the cap are dropped without a message.

## AGENTS.md deviations

- `apps/web/src/entities/comment/api/post-comment.ts` — §8: `postCommentSchema` is defined inline; it belongs in `packages/contracts/src/comment/comment-schema.ts`.
- `apps/web/src/entities/project/api/get-public-project-by-id.ts` — §8: `id` is checked with `cuidSchema.safeParse` instead of `parseInput(idSchema)`.
- `apps/web/src/entities/contact-message/api/get-paginated-contacts.ts` — §8: `filter.search` goes to Prisma unparsed.
- `apps/web/src/entities/media/api/upload-single-media.ts`, `apps/web/src/entities/media/api/upload-video-direct.ts` — §8: client code under `api/` without `'use server'`.
- `apps/web/src/entities/workspace-settings/api/get-workspace-settings.ts` — §8: not a server action; intentional per its comment, still outside the letter of the rule.
- `apps/web/src/entities/user-profile/api/get-public-user-profile.ts`, `apps/web/src/entities/project/api/get-paginated-public-projects.ts` — §8: closure-captured `userId` is absent from `cacheKey`. It is an env constant, so harmless today.
- `apps/web/src/entities/project/ui/project-timeline-item.tsx` — §3: deep cross-slice UI imports from the tag and tech-stack `ui/` folders.
- `get-all-public-contacts.ts`, `get-open-source-contributions.ts`, `get-all-public-tech-stacks.ts`, `get-paginated-public-tech-stacks.ts` and `get-paginated-public-tags.ts` (each under `apps/web/src/entities/<slice>/api/`) — §6: `CACHE_TAGS` used as an unstable_cache `cacheKey`; the rule says it is only for `revalidateTag`.
- `GITHUB_GRAPHQL` in `packages/github/src/open-source/fetch-merged-pull-requests.ts` and `packages/github/src/featured-work/fetch-featured-work-github.ts` — §11.7: hardcoded endpoint URL (the public GitHub GraphQL API).
- `packages/contracts/src/workspace-settings/settings-schema.ts`, `packages/contracts/src/project/public-project-schema.ts` — §8: schema file names are not `<slice>-schema.ts`.
